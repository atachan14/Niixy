## 追加ケースと結果

対象は[scripts/module_selector_browser_tests.py](../scripts/module_selector_browser_tests.py)。PC 1280×720とmobile 390×844（touch／is_mobile）で、ログイン済みownerと同じFieldを持つ公開ThreadIFをfixtureに使う。起点は次の3つ。

1. NiiMap地点選択→直接Thread作成。
2. NiiMapのRoom／BoardをURLから復元→Board内Thread作成。
3. NiiMapのRoom Summary→共通Workspace Room→Board一覧→Board内Thread作成。

| ケース | 結果・確認内容 |
| --- | --- |
| 通常操作（2 viewport × 3起点 × IF／Field = 12 subcase） | **成功**。追加、同じ項目の再選択、詳細Close→一覧Close。タイトルとField値、同じ起点form DOM、選択項目が重複しないこと、起点と一覧の隣接、Current右端とCloseの画面内表示を確認。Room幅と共通Workspaceの先行3Paneも保持。検索用IF／Fieldが作成用補助Paneと混在しないことも確認。 |
| reduced-motion限定操作（同じ12 subcase） | **成功**。`prefers-reduced-motion: reduce`、trackのtransition duration 0、補助Pane操作によるtransform transitionrun 0。同じ追加・再選択・Close・入力・位置のassertを確認。 |
| 遅い詳細応答（12 subcase、各2応答順 = 24パターン） | **成功**。実GETの本文を取得してからJavaScript Promiseで応答を保留。詳細Close後に同じ詳細nodeへ新requestを発行しても古い応答が新入力を上書きせず、editorは1個。補助Pane一式をCloseし別種を開いてから古い応答を解放しても、新PaneのHTML／種別を変えず、破棄済みPaneを復活させない。元タイトル・追加済み値・起点DOMを保持。 |
| focus後native scrollの直接回帰（PCの直接作成Field／mobileのRoom→Board IF = 2 subcase） | **成功**。入力focus handlerの初回align後に観測されたnative scrollを80pxで固定再現。テストから製品align APIを呼ばず、終了時scrollLeft 0と元の右端・隣接契約を確認。修正前は両case失敗。 |
| AGENTS指定の既存browser_smoke.py CLI | **成功、PC/mobile各17 checks、warning 0／browser error 0**。通常serverへ接続せず、既存WorkspaceBrowserTestsの隔離LiveServerに対するCLIだけを実行。 |

最終実行: **5テスト成功（selector 4 + 隔離CLI smoke 1）、185.772秒**。selectorは38 subcase（通常12 + reduced-motion12 + 遅い応答12 + native scroll2）。page error／console errorは0、既知の失敗残件0。一般Workspaceや全Djangoの過去成功件数には合算しない。

初回は3テスト中、通常操作のdesktop／NiiMap Room→Board／Field詳細で右端assertが1回失敗した（1182px、期待1280px、許容1px、146.857秒）。reduced-motionと遅い応答は成功。座標診断を加えた同じ通常テストを2回再実行し、42.202秒／43.244秒で成功したが、その結果だけで失敗を解消扱いにしていない。

アニメーション完了を待つ測定へ補強した修正前runでも、desktop直接作成Fieldで右端1199px／期待1280px、mobile Room→Board IFで250px／期待390pxと失敗した（146.831秒、2 failuresと、ずれにより次Fieldボタンが画面外になった1 error）。track transformは既に静止し、document scroll 0に対しWorkspaceのnative scrollLeftが81px／140px残っていた。単にアニメーション途中を測った結果ではない。

この観測を80pxのnative scrollで固定する直接回帰テストを追加し、製品修正前にPC／mobileとも同じ右端assertで失敗した（5.300秒）。これにより測定待機だけでは解決しないことを確認した。失敗時のログ・画像も保存する。

最小修正は[static/rooms/forms.js](../static/rooms/forms.js)の補助Pane detail focus handlerだけ。初回alignに加え、trackのアニメーション完了後のframeで既存setStage／alignによりnative scrollを解除する。focus世代・接続・現在のactiveElementを確認し、閉じた／別focusへ切り替えたPaneから位置を戻さない。共通Workspace・CSS・templateやcache versionは変えない。JS file-content-onlyなので通常serverのrestartは不要であり、実施していない。

計測はanimation frameとtrackの実アニメーション終了を待つが、期待座標への到達を待つ処理や期待値／1px許容誤差の変更は行わない。さらにnative scrollLeft 0をassertした。同じ正常操作・reduced-motion・遅い応答・直接回帰に、AGENTS指定の隔離CLI smokeを加えて最終確認し、5テストすべて成功した。

画像は`.artifacts/module-selector-followup/`へ出力し、以前のmodule-selector記録を上書きしない。既存smoke画像・ログも実行前に許可workspaceの`prior-browser-smoke/`へ複製した。両Board経路のPC/mobile IF／Field詳細、代表reduced-motion／遅延応答／focus補正画像と、smokeの`desktop-workspace.png`／`mobile-workspace.png`／`desktop.png`／`mobile.png`を目視確認し、Pane端・Close・入力・mobile幅に異常は見られなかった。smokeの末尾2画像はfixtureのstandalone Room Thread状態。ログと隔離runnerは許可task workspace `C:/Users/user/Documents/Codex/2026-10-06/task-5/`の`selector-qa-first.log`、`selector-geometry.log`、`selector-geometry-second.log`、`selector-qa-settled-before-fix.log`、`selector-focus-scroll-before-fix.log`、`selector-qa-final.log`、`run_selector_qa.py`に保持する。再現画像は同workspaceの`selector-native-scroll-before-fix.png`。commit対象ではない。

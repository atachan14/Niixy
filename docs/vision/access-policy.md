# 制限と Policy

## 方向性

Room と Thread は、誰がコンテンツを発見・閲覧・作成・返信・編集・管理できるかを定義できるようにする。将来の条件には Guest 状態、特定 Account、Room の所属やロール、AccountInterface の値、評価値などが含まれる。

複数の条件を一つの許可に並べた場合は OR、Room と Thread の両方に適用される条件は AND として扱う。発見と閲覧は意図的に分ける。たとえば、見つけられるが閲覧には条件を満たす必要がある Thread を表現できる。

## v0.3 の最小実装

画面の見出しは「制限」とし、その中に「発見制限」「閲覧制限」「書込制限」を置く。v0.3 で設定できる条件は Guest と NiixyAccount のみである。

これは汎用 Policy エンジンの先行実装ではない。v0.3 は固定された二条件だけを確実に保存・判定する。Thread の制限は作成時に確定し、作成後に編集しない。特定 Account、Room、ロール、Interface、評価値などを組み合わせる Policy の設計は、それらを利用する機能と合わせて後続バージョンで行う。

ログイン済み Account の作成者は、自分の Thread を管理するための閲覧・削除権限を常に持つ。各制限に条件が一つもない場合、ログイン済みの作成者以外にはその操作を許可しない。Guest は継続して識別しないため、Guest が作成した Thread を後から削除できない。

## 実装上の原則

発見制限は一覧・地図マーカー・検索結果に、閲覧制限は Thread 本文と投稿一覧に、書込制限は返信作成に適用する。すべてサーバー側で再判定するため、URL を直接開いた場合や画面を改変した場合にも制限を回避できない。

Room の共有と非公開 Thread の発見を実装する前に、汎用 Policy のデータ表現・継承・監査履歴を設計する。

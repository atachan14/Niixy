# Policy / Template 詳細引き継ぎ

作成日: 2026-10-05
実装の読取基準: `27d806b`（v0.9完了）付近の作業ツリー。

このフォルダは、会話で決めた仕様のうち既存docsだけでは読み取りにくい事項を補う。別AIがVisionを編集中のため、既存Vision・Roadmap・Version要件は変更せず、独立した引き継ぎ資料として追加した。ここで新しいVersionの実装を指示・承認するものではない。

## 読む順番

1. [確定仕様と構造](policy-template-spec.md): Policyの境界、設定の構成、Templateの適用時点。
2. [不可時のUI](denied-ui.md): Room / Board / Threadごとの表示、参加不可と書き込み不可の違い。
3. [実装との差分](implementation-gaps.md): 実際に読んだコード、仮実装、既存docsの古い記述。
4. [今後の候補と未決事項](next-steps.md): Version未割当の候補と、実装前に詰める点。

Workspace、開発サーバー、隔離テストの引き継ぎは既存の[開発引き継ぎメモ](../handoff.md)を参照する。

## 資料の扱い

- **確定方針**: 会話で合意した仕様。未実装でも実装済みと書き換えない。
- **現行実装**: この資料作成時にコードで確認できた挙動。将来の正解とは限らない。
- **未決・提案**: 実装上必要になりそうでも、ユーザーがまだ確定していない事項。
- 会話には旧案が含まれる。後の訂正を優先し、旧案と新案を足し合わせない。
- この資料以降にユーザーや別AIが更新した仕様・コードを巻き戻さない。開始時に差分と更新内容を確認する。
- コードが仕様と異なるからといって、既存データの公開範囲が変わる修正を無確認で行わない。特に旧ThreadPolicyの移行は別途設計が必要。

`docs/memo/inbox.md`はユーザー専用。読み取り・編集・削除・ステージングをしない。この資料は会話に提示された内容と、それ以外のdocs・コードから作成した。

## 既存資料だけでは不足する理由

[Visionの制限とPolicy](../vision/access-policy.md)には、Templateが作成時だけ作用する旧説明が残っている。一方、[決定記録](../vision/decisions.md)と[v0.9要件](../v0.9/requirements.md)では「編集可能な対象設定を編集する時にも強制を適用する」へ更新されている。

不可時の共通原則は決定記録にあるが、RoomはPopup、BoardとThreadはBody内、返信不可は投稿欄の位置に枠付き表示、という画面ごとの差は一か所に揃っていない。LayoutとTemplateをPolicyの外へ出した最終構造も、会話の旧ツリーだけを読むと取り違えやすい。

**v0.9完了は、Policy構想全体の完成ではない。** BoardPolicyと共通評価器が先行し、RoomPolicy、旧ThreadPolicyの移行、Template、Layout適用は残っている。
